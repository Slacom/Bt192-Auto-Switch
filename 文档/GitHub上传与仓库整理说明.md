## 本地工程与GitHub源码范围不同

本地工程仍保留历史APK和复核材料，便于追查连接秒切回归；**它不会作为一个完整大文件夹公开上传**。新的[忽略规则](<../.gitignore>)采取白名单：

- 根README、AGENTS、忽略规则与文本属性；
- 当前016源码、Manifest、测试和增量驱动；
- 015冻结Scroll，供源码模型负对照；
- 本机MT客户端；
- 当前修改计划、本说明及016有限审核文字报告。

不上传：生产/TEST_ONLY APK、所有旧大档案、签名私钥/keystore、MT会话、构建JSON、原始运行日志、截图、设备验收数据及历史交接/旧文档。公开证书指纹不是私钥；`.pub.pem`不是发现私钥的证据。本次未发现标准命名的私钥/keystore/.env文件，当前016目录的常见密钥标记检查无匹配，**不等于完成所有历史内容的全面泄密审计**。

白名单有意仅上传当前开发所需源码。以后新增目录/文档不会自动加入Git，需审阅后更新规则。完整旧审查工具和JSON不随clone提供，报告里指向这些本地材料的链接仅在原本地工程有效。

## 构建与历史可复现性限制

这是smali＋MT增量工程，不是可直接打开Android Studio独立Gradle编译的完整源码。构建需另行提供精确015基线及本机MT签名环境；两者不在Git中。不得把不完整公共仓库描述为能“一键重建同证书全部历史APK”。源模型测试的本地依赖包含已公开的015Scroll；历史全量审查/设备证据不包含在公共提交里。

保留本地旧生产包是为了回归对照，不表示它们都已实测通过。016目前仍有用户反馈的分钟级切换与动画不足，不能打稳定版标签，也不能把历史审核文字当当前功能修复成功。

## 手动上传步骤（尚未执行）

以下只是用户以后确认的操作示例。本轮没有在项目中执行git init、commit、创建remote或push，也未登录GitHub。

```sh
# 在项目根目录执行；如需私有仓库，先在GitHub选Private。
git init
git add .
git status --short
# 必须人工检查暂存列表与内容；没有APK、原始日志、私钥或个人设备信息。
git diff --cached --stat
git diff --cached
# 检查后，再配置自己的提交身份并提交。
git commit -m "Import current smali source and development plan"
git branch -M main
git remote add origin <你的GitHub仓库URL>
git push -u origin main
```

`.gitignore`只约束Git工具，**GitHub网页直接拖拽整个本地目录不会替你遵守这些规则**；不要把本地剩余数百MB档案、设备日志和原始备份拖上去。若用网页上传，应只取白名单文件并保留相对目录。

`.gitignore`也不会阻止已经被强制暂存/跟踪的文件：以后如用`git add -f`或修改规则，需重新审阅。当前项目原本没有`.git`，因此此次不存在清除旧Git历史的问题。
