# V3.1规划方向

**状态：需求记录／待研究，尚未实现，不属于当前V3.0功能，也不承诺交付日期。**

GitHub以两个Issue归入[V3.1里程碑](https://github.com/Slacom/Bt192-Auto-Switch/milestones)跟踪，完成同步后可在[V3.1问题列表](https://github.com/Slacom/Bt192-Auto-Switch/issues?q=is%3Aissue%20milestone%3AV3.1)查看；本文件为仓库内的长期记录。用户提供的截图只作为需求参考，不将截图中的设置直接等同于所有设备可用能力，不上传原始截图或个人设备信息。

## 方向一：自定义目标采样率与LHDC传输比特率

### 用户需求

不再只自动切到192kHz。允许用户为耳机选择目标采样率，并增加LHDC传输比特率／播放质量设置。

截图参考选项：

- 偏重低延迟：256kbps。
- 偏重连接质量：400kbps。
- 兼顾音频和连接质量：500／560kbps。
- 偏重音频质量：900kbps。
- 自适应比特率。

上述仅为用户当前系统显示的选项，不是通用LHDC参数表或本项目已支持列表；不同LHDC版本、ROM和耳机可能不同。采样率与传输比特率分别是不同维度，不混同PCM位深、LDAC播放质量或其它编码器设置。

### 初步设计方向（待确认）

- 继续按设备保存独立目标；采样率仅列当前设备可选值，例如44.1／48／96／192kHz，不能假定全部支持。
- 比特率提供自适应和设备实际支持的固定档位；可考虑“保持系统当前／不干预”选项。
- 界面区分目标值、实际读取值和未知／不支持；不能将写入请求成功直接显示为实际生效。
- 升级迁移保留原设备关联、独立开关和排序；旧用户默认沿用192kHz，未主动设置时不新增固定码率干预。

### 待研究与验收

- [ ] 核对各LHDC版本及小米系统实际接口、可选能力和厂商字段编码，不照抄其它编码器的映射。
- [ ] 确定两参数写入的顺序、协商反馈、重试和失败处理，避免反复重连或覆盖其它编码参数。
- [ ] 保留连接资格、设备匹配、epoch／任务过期保护，配置变化不能让旧任务重写新目标。
- [ ] 覆盖断连、重连、切换设备、编码器变化、固定／自适应切换及不支持目标时的行为。
- [ ] 仅在用户后续明确授权后开展实际设备setter测试；本轮不调用蓝牙接口或修改参数。

## 方向二：下拉快捷开关与无障碍状态检测／按需恢复

### 用户需求

在系统下拉控制中心添加BT192 Switch快捷按钮，直观显示无障碍服务是否激活，并研究类似GKD的“无感保活”：下拉控制中心时检测状态，条件允许时恢复服务。

### 需要区分的状态与权限

- 系统设置中已授权／已启用，不等于当前服务实例已连接或后台工作正常。
- 快捷开关入口、状态指示、点击触发的恢复、下拉触发的检查，与持续存活不是同一承诺。
- 优先采用系统Quick Settings／TileService机制；系统限制或用户未授权时，提供明确提示及手动恢复入口。
- 是否加入可选自动恢复，需要后续单独设计：普通模式与额外授权模式分开，不默认要求WRITE_SECURE_SETTINGS、Shizuku或Root。
- 不擅自重新开启用户明确关闭的服务，不影响其它应用的无障碍设置，不恢复无关的读屏或手势权限。

### GKD参考与当前研究状态

- [GKD官方仓库](https://github.com/gkd-kit/gkd)是参考对象。搜索索引的官方项目说明标注GPL-3.0-only，研究机制不等于可以无条件复制其代码；若复用实现，须先核许可兼容性及义务。
- [GKD官方讨论：服务故障与恢复](https://github.com/orgs/gkd-kit/discussions/814)提到，已配置相关功能时，下拉通知栏可触发恢复。它是行为说明，不证明所有ROM都有效，也不是本项目实现证据。
- [Android官方Quick Settings文档](https://developer.android.com/develop/ui/views/quicksettings-tiles)说明TileService有独立的监听生命周期，不能假定离开onStartListening／onStopListening区间仍持续存活。不能把添加磁贴等同于永久保活。
- 本轮尝试读取GitHub及Android官方页面全文时，工具因域名解析为非公网地址而拒绝；未换通道绕过。当前只取得公开搜索索引和官方讨论摘要，**尚未亲读完整GKD源码或核准具体类名／调用链**。后续应固定GKD版本与提交，再核磁贴监听、状态源及恢复权限分支；不以推测冒称源码结论。
- 用户截图还显示GKD有普通无障碍、写入安全设置增强和自动化等模式，不能把某一模式下的恢复能力当普通应用必然具备。

### 待研究与验收

- [ ] 固定并阅读GKD对应版本的磁贴服务、Manifest声明及恢复调用链，分清普通与增强权限分支。
- [ ] 设计TileService的激活／非激活监听模式、状态刷新与点击动作，明确显示异常或未知状态。
- [ ] 定义服务连接状态与后台工作状态的可靠来源，避免只读授权开关而误判存活。
- [ ] 验证系统回收、进程崩溃、下拉／收起面板、磁贴添加／移除、重启、手动禁用等场景。
- [ ] 在小米15与小米Pad 7S Pro分别验收；不把下拉后能恢复描述成全时、全ROM保活保证。
